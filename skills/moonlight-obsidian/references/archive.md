# 论文目录、导航与增量归档

## 先查已有分支

先检查 `论文阅读/` 的目录名，再用 paperId、DOI 或规范来源链接定位候选入口和标识，只读相关候选笔记，避免每次扫描全库正文。搜索返回有截断时不能断言不存在。目录名只是显示名称，论文身份以已核实标识及作者等信息确认。同一 DOI 对应不同修订版、同一论文在 Moonlight 重复上传或有多个匹配分支时，先说明差异并确定复用目标，不自动合并。

对已确认的旧分支，优先沿用已有 `论文原文/阅读入口.md` 或同等入口。补充真实的规范 Moonlight 链接可让现有导入器识别该分支。修改先读、保留原文并做版本检查；没有入口再新建，不同时创建多个等价入口。若已有 `.moonlight-paper.json` 指向其他 paperId，当前导入器会优先用该标识，单加链接不能解决；不要改标识或创建重复分支，需明确处理该重复来源的方式。

## 四目录辅助工具

现有 Moonlight 导入器要求有完整且非空的会话。只保存精读/本次问答、原论文尚无历史讨论时，可用随技能提供的目录工具。

```sh
python3 <技能绝对路径>/scripts/ensure_paper_dirs.py --vault '/绝对路径/Obsidian库' --paper '已确认的论文分支名'
```

默认只检查并输出 JSON 计划。加 `--apply` 才建立缺失目录。工具不写笔记、元数据或附件，不重命名、删除或合并任何内容；没有有效 `.obsidian` 目录、名称含路径分隔符/控制字符、目标为符号链接或被普通文件占用时拒绝。先检查全部目标，避免已知冲突导致部分创建；实际文件系统异常仍可能留下已创建的空目录，不宣称事务回滚。创建后从报告核对四目录。

目录名称须来自已核实论文；辅助工具不会判断是否已有同一论文。只读请求不调用 `--apply`。取得保存授权后可在当前执行权限允许范围内直接创建，无需为普通空目录反复询问。

## 一个稳定入口

首次归档或用户要求整理时，可在论文分支根建立 `论文导航.md`，保留四个固定子目录。已有相同功能的主页就复用，不再新建平行入口。简单保存时只更新与此次内容相关的链接。

导航正文按实际存在的内容设置：

- 原文入口与已保存 PDF；只有远程链接时明确为远程来源。
- 精读、推导和图表解读；链接到实际文件。
- 最近一次成功导入返回的 Moonlight 会话索引；历史索引继续保留。
- 已保存的专题问答和真正未解决的问题。
- 阅读进度：实际读取页段、待核实页/公式、附件缺口。

仅在有证据时写 frontmatter，可使用 `title`、`paper_id`、`doi`、`moonlight_url`、`updated`。字符串需正确 YAML 转义，日期使用用户时区；未知项省略。`paper_id` 等是便于检索的笔记元数据，不替代导入器的 `.moonlight-paper.json`。不要伪造作者、DOI、下载日期或文献管理标识。

按事实记录进度，例如“本次读取 PDF 第 3–5 页；图 2 尚未目视核对”。不要用单个 `complete: true` 混淆会话采集、附件保存、全文阅读与事实核验。后续接着读时先看导航及当前问题相关笔记，避免重复读取；补读缺失部分后才更新覆盖范围。

导航更新只修改相关小节：先查文档结构，带版本做局部编辑；用户正文、任务状态和其他小节保留。相同链接不重复追加；存在用户同名标题时按工具返回的确切目标定位，不重写整份导航。

## 文件名与同主题续写

使用能辨认内容的短标题，例如 `解释/方法总览.md`、`解释/损失函数推导.md`、`问答/为什么需要重排序.md`。这些是命名示例，不是每篇必建的清单。用户已有命名习惯时沿用。

保存前查同主题笔记；用户说“继续”“补充”“修正这条回答”时优先更新对应内容，保留原有人工材料和仍有价值的讨论。只有主题不同、用户要求独立记录或确需保留独立版本时才新建。一般笔记不强制加日期、数字序号或“最终版”；实验/会议等时间本身有意义时可用日期。文件名移除路径分隔符、控制字符及 Obsidian 链接冲突字符；规范化后检查同名，不能覆盖不同主题。

## 快照与更新

Moonlight 导入器的 `Moonlight-讨论-…`、`Moonlight-解释-…` 和摘要命名索引是不可变快照。保留其文件名及内容；不把它们批量改成人类可读文件名，也不自动清理旧版本。通过导航和导入器索引提供可读入口。

相同内容重复导入跳过；追加追问会生成新快照。当前导入器仍重新采集当前论文全部可访问会话，增量仅指本地写入去重，不代表网络采集增量、实时同步或后台定时任务。对同一导入不要先调用完整 conversations 再调用 import 重复采集；直接让 import 采集即可。导航的最近索引取自本次成功返回的 `index`，不是排序文件名得到的。问答数量区分会话数、消息数和本次新建文件数；不把同一会话的多个快照累计成独立讨论。工具的 `created`/`unchanged` 是会话快照计数，不包含所有目录、标识及索引写入，汇报时说明计数对象。

采集失败时不更新“最近成功归档”；若中途已有写入则如实报告。不要自动删除锁文件或清理冲突内容。需要合并重复分支、删除历史或批量重命名时，先列具体影响与引用修复计划，用户明确要求这类操作后再执行。

## PDF、配图和链接

只在用户要求保存原文/附件或完整离线归档时下载。先查已有文件；文件名一致不代表内容相同，确有冲突时保留原文件并识别版本。补充材料用可辨认名称。使用当前可用的合法原文来源，不把 HTML 错误页当 PDF 保存。

远程图片保留远程来源状态；下载成功并核实后才改成本地引用。配图可用 `图02-检索流程.png` 等名称，图号和描述必须来自实际内容。同图先复用，必要时按内容摘要去重，不根据相似文件名判定字节相同。导航、问答与图片引用使用含论文分支的完整库内目标；Markdown 相对链接按所在文件位置计算，带空格路径用尖括号或适当编码。

不记录临时签名下载地址或令牌到长期元数据；保留可回访的论文来源页。附件缺失、远程链接失效和无法目视核对分别说明，不把它们概括成已完成归档。
